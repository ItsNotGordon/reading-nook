# PRD: Reading Nook (Product)

**Status:** Canonical spec for the **shipped app** and **near-term direction**  
**Supersedes for day-to-day work:** navigation, data model, and “what exists today” details in `Reading_Nook_PRD.md` and `Reading_Nook_Updated_PRD.md` (those remain useful for historical requirements and deep algorithm notes).

---

## 1. Product Overview

**Product Name:** Reading Nook  
**Product Type:** Small, mobile-first reading tracker web app  
**Platform:** Next.js (App Router), TypeScript, Tailwind CSS  
**Audience:** You and a small circle of friends—not a mass-market social network  
**North star:** A cozy place to **track what you read**, **rank what you finish**, and **discover what to read next**, with a path to **deploy on the web** so friends can each have their own nook.

Reading Nook started as a STAT 280 class project; that phase is complete. The product is now a **personal / friends-scale app**: build something real enough to share, grow infrastructure only as needed, and avoid optimizing for huge traffic or viral growth.

The product combines:

```txt
Goodreads-style library shelves
+
Beli-style sentiment buckets and pairwise ranking (no star ratings)
+
catalog search + offline recommendations, with client-side taste personalization
```

**Today:** each browser keeps its own library in `localStorage`; catalog and base recommendations ship as static JSON.  
**Tomorrow (intentional, not urgent):** auth, hosted data, and optional friend features so everyone can use the same deployed URL without sharing one device.

---

## 2. Product Philosophy

Reading Nook does not ask:

```txt
How many stars would you give this book?
```

It asks:

```txt
How did you feel about this book?
Which book did you like more?
```

**Scores are derived** from sentiment bucket + rank position inside that bucket, not typed in by the user.

This should feel:

- less arbitrary than five stars  
- personal and honest  
- easy to update when opinions change  
- useful for recommendations and (later) comparing taste with friends  

The UI should feel like a **reading companion**, not a feed. The Friends tab exists as a **placeholder** until real sharing is built.

## 3. Vision: Friends-scale, not “huge app”

### What we are building

| Goal | Meaning |
| ---- | ------- |
| **Deployable** | A stable URL (e.g. Vercel) friends can open on their phones |
| **Per-person libraries** | Each friend has their own books, progress, and rankings (requires auth + database—not yet shipped) |
| **Small scope** | Polish core loops before adding clubs, feeds, or heavy ML |
| **Scalable foundations** | Choose patterns (Supabase/Postgres, APIs) that won’t need a rewrite when the friend group grows slightly |

### What we are not building (unless explicitly chosen later)

- Aiming for large-scale popularity or engagement metrics  
- Full social network (followers, comments, public feeds)  
- STAT 280 Apriori + KNN as the main recommendation roadmap  
- Star ratings or manual 1–10 entry  

### Reasonable success for this phase

Friends can:

1. Open the deployed app on mobile  
2. Add and shelve books, track progress, finish and rank reads  
3. See personalized recommendations on the Add screen  
4. (Future) Sign in and keep the same library across devices  
5. (Future) Opt in to see a friend’s shelves or taste overlap

## 6. Data Model

Types live in `app/src/lib/types.ts`. This is the **authoritative** shape.

### 6.1 Book (catalog metadata)

```ts
type Book = {
  id: string;
  title: string;
  author: string;
  coverUrl: string;
  totalPages: number;       // 0 = unknown
  genres: string[];
  description: string;
  publishedYear?: number;
  averageRating?: number;
  ratingsCount?: number;
};
```

Books enter `AppState.catalog` when shelved or merged from catalog/rec JSON.

### 6.2 Shelf

```ts
type Shelf = "want_to_read" | "reading" | "finished";
```

Display names: **Want to Read**, **Currently Reading**, **Finished**.

### 6.3 Sentiment bucket

```ts
type SentimentBucket = "liked" | "okay" | "disliked";
```

| Bucket | Score range (derived) |
| ------ | ----------------------- |
| liked | 7.0 – 10.0 |
| okay | 3.6 – 6.9 |
| disliked | 1.0 – 3.5 |

### 6.4 Progress mode

```ts
type ProgressMode = "exact" | "estimated";
```

- **exact:** `currentPage` / `totalPages` → percentage  
- **estimated:** `estimatedRange` as inclusive 0–1 fractions (e.g. `[0.5, 0.75]`)

### 6.5 UserBook

```ts
type UserBook = {
  bookId: string;
  shelf: Shelf;
  progressMode: ProgressMode;
  currentPage: number | null;
  estimatedRange: [number, number] | null;
  finishedAt: string | null;        // user-facing finish date (ISO)
  finishedSortAt: string | null;    // latest finish/rerate action; Finished shelf order
  sentimentBucket: SentimentBucket | null;
  derivedScore: number | null;
  addedAt: string;
  notes: string;
};
```

**Finished shelf ordering:** newest `finishedSortAt` (then `finishedAt`, then `addedAt`) first—not by derived score.

### 6.6 Bucket rankings

```ts
type BucketRankings = {
  liked: string[];
  okay: string[];
  disliked: string[];
};
```

Ordered `bookId` lists per bucket. **Source of truth for rank order;** derived scores are recomputed from order.

### 6.7 User profile

```ts
type UserProfile = {
  displayName: string;
  tagline: string;
};
```

### 6.8 App state

```ts
type AppState = {
  version: 1;
  catalog: Record<string, Book>;
  userBooks: Partial<Record<string, UserBook>>;
  bucketRankings: BucketRankings;
  profile: UserProfile;
};
```

Persisted under storage key `reading-nook-v1` (see §7).

## 7. Persistence

- **Mechanism:** `localStorage` via `app/src/lib/storage.ts`  
- **Key:** `reading-nook-v1`  
- **Behavior:** load on startup; save after state changes; tolerate missing/corrupt data with migration helpers and legacy sentiment bucket mapping (`loved` → `liked`, etc.)  
- **Limitation:** data is per browser per device; clearing site data loses the library  

**Friends-scale implication:** auth + server persistence are required before “deploy and share one URL” works for multiple people.

## 9. Add Tab (Search + Recommendations)

Single screen (`AddTabClient`): catalog search on top, recommendations below.

### 9.1 Catalog search

- Fetches `/api/books/search?q=…` (Open Library via server); queries prefer `language:eng`  
- **Titles** that look like translations (e.g. Spanish article/accented text) are normalized to an English edition title via Open Library `editions.json` (`translation_of` or English-language edition)  
- **Genres** come from Open Library `subject` fields (BISAC `/` paths and LOC `*--Fiction` mapped to ~40 canonical labels; capped at 6). Users can **add or edit genres** from that same list when shelving a book or from Ratings book detail (optional on add; Add genres / Edit in detail sheet)  
- On shelf add, `/api/books/work?id=openlibrary:…` enriches **description**, subjects, and **title** (when heuristic applies) from work/edition JSON  
- Requires **at least 2 characters** to show matches (`MIN_QUERY_LENGTH`)  
- Filters out books already in `userBooks`  
- Max **20** results shown  
- Picking a book opens **shelf picker** (Want to Read / Currently Reading / Finished)  
- Choosing **Finished** triggers finish flow (sentiment → pairwise → scores)  

### 9.2 Recommendations block

- **Open Library only** for live recs: unshelved `catalog` rows (`openlibrary:…`) plus optional **OL discover** (`/api/books/discover`, `sort=readinglog` by top taste genres when the catalog pool is small)  
- **No runtime Goodreads pool:** the app does not load or merge `recommendations.json` on the Add tab (file may remain in repo until removed)  
- When the user has taste signals (finished books with sentiment), **`appNativeRecommendations.ts`** runs **weighted Apriori + sentiment KNN** (`app/src/lib/recommender/`)  
- **Weighted taste:** signed genre affinity (`liked` +3, `okay` +1, `disliked` −2 per genre); frequency matters  
- **Apriori (single-user):** book-level weighted baskets; genre co-occurrence rules and target genres  
- **KNN:** k-nearest finished books by genre (and author match); disliked books as negative neighbors  
- **Popularity blend:** OL `readinglogCount` / `ratingsCount` nudge the hybrid score (~28% weight) so well-read titles surface; **serendipity slots** (~6 of 30) reserve lower-popularity, high-taste-fit picks  
- **Hybrid score:** taste + popularity; disliked author/genre penalties; `source` = `Apriori + KNN`  
- Hides books already in the user library  
- Genre filter chips when rec rows exist  
- Shows up to **30** visible recs (`RECS_VISIBLE_COUNT`)  
- Tap rec → shelf picker (discover rows are display-only until shelved; shelf flow adds to catalog)  
- Class notebook and `recommender/generate_recommendations.py` are **not** the live engine  

### 9.2.1 Recommendations (deprecated Goodbooks path)

**Previously:** `recommendations.json` from Goodbooks CSVs supplied numeric `bookId` strangers. **Now:** candidates are catalog + OL discover only. `npm run build:recs` is optional legacy tooling, not required for the Add tab.

| Layer | Role |
| ----- | ---- |
| **App-native `Book`** | `catalog[bookId]` — title, author, cover, canonical genres, optional OL popularity fields |
| **Open Library ids** | `openlibrary:OL…` everywhere |
| **Taste signals** | Finished books with sentiment |
| **Discover API** | Popular works in user's top genres when catalog unshelved count &lt; 15 |

### 9.3 Loading / errors

- Catalog search loading/errors on Add  
- Recs: brief "Finding popular Open Library picks…" while discover loads; empty copy when no taste or no candidates (search OL to grow catalog)

UI may note that exact pages vary by edition.

## 11. Finish Flow

When a book moves to **finished**:

1. Set shelf to `finished` and timestamps (`finishedAt`, `finishedSortAt`)  
2. **Sentiment picker** — liked / okay / disliked (`FinishBookSheet`)  
3. **Pairwise ranking** — binary-search insertion into `bucketRankings[bucket]` (`PairwiseComparisonSheet`)  
4. **Recompute** `derivedScore` for all books in that bucket (`computeDerivedScores` in `ranking.ts`)  

Pairwise question pattern: prefer new book vs existing book at midpoint until insert index is found.

---

## 12. Derived Scoring

Formula (curved within bucket):

```ts
// rankIndex: 0 = top of bucket (best)
p = 1 - rankIndex / (totalBooks - 1)
curve = p^0.6
score = bucketMin + curve * (bucketMax - bucketMin)
```

Single book in bucket → bucket **max** score.  
Scores are rounded to one decimal.  
Buckets use non-overlapping ranges (see §6.3).

## 13. Ratings Tab

**Purpose:** Personal list of rated/finished books—not a competitive leaderboard.

**Behavior:**

- Merges all books from `bucketRankings` (liked, then okay, then disliked order preserved within merge)  
- **Sorts by `derivedScore` descending** for display  
- Row: cover, title, author, score badge, sentiment styling  
- Tap row → detail sheet (view/edit notes, sentiment, re-rank where supported)  
- Empty state links to Add  

Label **“Leaderboard”** is avoided in primary nav; legacy `/leaderboard` redirects to `/ratings`.

---

## 14. Profile Tab

Shows:

- Editable **display name** and **tagline**  
- Counts: total shelved, reading, finished, want to read  
- Average derived score (finished books with scores)  
- Sentiment breakdown (liked / okay / disliked counts)  
- Top genres (from finished books, shared logic with recs genre chips)  
- Top authors (prefer liked finished, else all finished)  
- **Favorite book** — top of liked bucket, else okay, else disliked

## 17. Friends-Scale Roadmap

Ordered by typical dependency. Build when you need friends on the deployed app—not all at once.

### Phase A — Deploy current local-first app

- `npm run build:books` && `npm run build:recs` && `npm run build`  
- Deploy to Vercel (or similar)  
- Document that **each visitor still has separate local data** until Phase B  

### Phase B — Identity and database

- **Supabase** (or Postgres + auth): users, libraries, `user_books`, `bucket_rankings`, profile  
- **Authentication:** email magic link or OAuth—keep friction low for friends  
- Migrate client `AppState` to API reads/writes; keep types aligned with §6  

### Phase C — Cloud sync

- Same account on phone and desktop  
- Simple conflict strategy (last-write-wins or per-field merge for notes/progress)  

### Phase D — Friend features (small group)

- Friend invites or allowlist (no open signup required)  
- Opt-in visibility: shelves and/or finished rankings  
- **Taste comparison:** shared genres, overlapping favorites, score correlation—lightweight, not a feed  

### Phase E — Better catalog and recs

- Hosted **book search API** (Open Library, etc.) instead of only static `books.json`  
- **Per-user recommendations** generated server-side from ranking signals—not only global `recommendations.json`  

### Deprioritized

- Notebook Apriori + KNN extraction as default next step  
- Reviews, comments, notifications, book clubs, real-time collaboration

## 19. Run, Build, and Deploy

From `app/`:

```bash
npm run build:books    # requires ../git-forked-database/*.csv
npm run build:recs     # requires Python + recommender/
npm run dev            # local development
npm run build && npm start   # production serve (must build static JSON first)
```

**Note:** `next start` serves the last `next build` output. After changing `public/data/*.json` or app code, run **`build:books` / `build:recs` as needed**, then **`npm run build`** before `npm start`.

For LAN/mobile testing during dev:

```bash
npm run dev -- --hostname 0.0.0.0 --port 3000
```

Use the machine’s LAN IP on other devices, not `localhost`.

## 20. Success Criteria

### Shipped (local-first)

1. User can open Library, Add, Ratings, Profile on mobile  
2. User can search catalog (2+ chars), add to shelf, track progress  
3. User can finish a book, pick sentiment, complete pairwise rank, see derived score  
4. Ratings tab reflects rankings; Profile shows stats and top genres  
5. Recommendations load on Add, personalize after enough finished books, and can be shelved  
6. Refresh does not lose data (same browser)  

### Friends-scale (next milestones)

7. Deployed URL loads reliably for friends  
8. Each friend has their own account and library (Phase B+)  
9. At least one meaningful friend feature (e.g. view a friend’s finished list or taste overlap) without building a full social network
